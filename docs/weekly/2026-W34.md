## 問題修正

### Stop keeping the account password in the browser
`9d96a6c` · 2026-08-21

Ticking "Remember credentials" wrote the user's Supabase password to localStorage in plain text, and read it back to refill the field on the next visit. Nothing else used it - it was only ever a convenience - and the login inputs already carry autocomplete="username" and "current-password", so the browser's own password manager was always able to do this properly: encrypted, behind the operating system, and not readable by any script on the page.

## 調整與優化

### Keep the planning notes out of the public repo
`54d1c87` · 2026-08-21

專案規劃/ holds a working document that catalogues this system's open weaknesses and where each one lives - attachments still served from permanent public URLs, closed records deleted on a timer. The repo is public, and the attachment one is not fixed yet. A list like that saves an attacker the survey.

### Drop the per-item weights from the certification checklist
`57a587e` · 2026-08-19

How the eighty percent is divided is our arithmetic. Printing 11.4% against every row invited the reader to check the sum rather than read the list, and turned a question about what is left to test into a question about how the number is built. The dial already carries the figure anyone acts on.

### Drop the temporary test schedule
`b2c2b36` · 2026-08-17

Run #3 fired from the schedule and succeeded, so the trigger works - it was simply 73 minutes late, which is ordinary queue delay rather than a fault. That run also settled the mail question: a scheduled run reaches the mailbox, while the two manual ones never did, because GitHub does not email you about activity you triggered yourself.

### Move the weekly schedule off the top of the hour
`a372891` · 2026-08-17

The first scheduled run never appeared. Runs queued at :00 compete with everything else cron-driven on the platform and get delayed or dropped; GitHub documents this and recommends against the exact hour. 01:23 UTC keeps it at roughly the same time in Taipei without sitting in that queue.

### Call the sample field PAL ID
`9a3703b` · 2026-08-19

The lab identifies a unit by its PAL ID, so that is what the field should ask for. The name says what to type, which is what the e.g. placeholder was standing in for, so the placeholder goes with it.

### Project Log: describe a Chromebook by its OS and transducers
`236da28` · 2026-08-18

Chromebook was left with no product type at all, on the grounds that it is kept as a plain record. That was too blunt: what the platform actually needs recorded is which OS the machine runs and what it has to test with, neither of which fits the Product Type dropdown the other platforms share. It gets its own pair of fields hung off the platform instead.

### Beat the leading tick on the project detail dial
`a1bbb6e` · 2026-08-18

A dial that keeps moving reads as "still loading" rather than as a settled number, and a list of fifteen cards all animating at once has nowhere quiet to look. So the flow is confined to the one place a single dial is on screen, and to the one tick that means something: the frontier between done and not done.

### Project Log: track certification progress per project
`a3554d6` · 2026-08-18

A project's certification state lived only in the daily logs, so answering "how far along is this one" meant reading them. This derives it instead, from what the device is and what has been logged against it.
